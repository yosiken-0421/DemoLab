## Features to preserve
- Single static HTML/CSS/JavaScript Web app, currently NOT a native iOS app. No build step.
- Browser camera via getUserMedia; high-resolution still photo input (`<input capture>`); Tesseract.js 5.1.1 jpn+eng from jsDelivr (traineddata 4.0.0_best_int).
- Recognized text drawn over the frozen captured frame (not live AR). Results require user confirmation before saving.
- Date, store, amount, tax rate/tax amount, category, note; manual add/edit/delete/reorder; automatic monthly grouping.
- In-browser workbook (`ReceiptExcel.buildExcel`): 13 sheets (年間集計 + 1月〜12月); JSON backup and restore.
- Records in localStorage `receipt-note-records-v1` (format unchanged; provide a migration for any schema change).
- Never store receipt images, never send them anywhere except the local OCR worker.

## OCR architecture (v5, 2026-11-09)
Script blocks in index.html: `ReceiptExcel` → `ReceiptOCR` (pure, unit-tested) → app IIFE.
1. `analyzeImage`: paper rectangle (Otsu on a 96px grid with 3×3 dilation) + text skew (projection profile of vertical gradients, ±15°).
2. Pass 1: whole frame ≤2400px, deskewed, PSM 3 → layout (line boxes, baselines, line height). If deskew made it worse, retried at 0°.
3. Pass 2: text area ∪ paper, deskewed, upscaled to ~38px line height (≤3×), illumination-normalized, split into ≤3 tiles of ≤5.5 MP, PSM 4.
4. Optional pass 3 (PSM 6, no normalization) only when the total is still missing/conflicting.
5. `combinePasses`: totals cross-checked against お預り−お釣り, 小計, tax-rate targets. Unverified totals that contradict an arithmetic consensus, single-digit totals, and disagreeing passes → amount left blank; candidates shown as tap-to-fill chips. Dates in the future or conflicting → blank.
6. Overlay: `#ocrFrame` is positioned with object-fit:contain math (`layoutOCRFrame`, ResizeObserver); boxes are % of the image and may be rotated. Previous version drifted ~26px because the stage resized after rendering.
- Tesseract.js 5.1.1 facts (verified in its source): `data.lines`/`words` are flattened from `blocks` by `circularize`; `bbox {x0,y0,x1,y1}` and `baseline` exist on lines/words; `hocr`/`tsv` are generated by default (we now disable them); `rotateAuto` would return rotated coordinates (not used).

- `npm install && npx playwright install chromium webkit && npm test` (unit + E2E Chromium + E2E WebKit); `node ocr-bench.mjs` for OCR accuracy on 20 synthetic, fictional receipts.
