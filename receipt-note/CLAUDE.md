## Features to preserve
- Single static HTML/CSS/JavaScript Web app, currently NOT a native iOS app. No build step.
- Browser camera via getUserMedia; high-resolution still photo input (`<input capture>`); Tesseract.js 5.1.1 jpn+eng from jsDelivr (traineddata 4.0.0_best_int).
- Recognized text drawn over the frozen captured frame (not live AR). Results require user confirmation before saving.
- Date, store, amount, tax rate/tax amount, category, note; manual add/edit/delete/reorder; automatic monthly grouping.
- In-browser workbook (`ReceiptExcel.buildExcel`): 13 sheets (年間集計 + 1月〜12月); JSON backup and restore.
- Records in localStorage `receipt-note-records-v1` (format unchanged; provide a migration for any schema change).
- Never store receipt images, never send them anywhere except the local OCR worker.

## OCR architecture (v6, 2026-11-10: field-focused)
Goal (user, 2026-11-10): only the fields the monthly Excel needs must be read reliably: 日付, 店名, 金額（税込）, 税率, 税額.
Script blocks in index.html: `ReceiptExcel` → `ReceiptOCR` (pure, unit-tested) → app IIFE.
1. `analyzeImage`: paper rectangle, text skew, and printed character height (`estimateLineHeight`, row profile).
2. `makePyramid`/`makeViewP`: large reductions come from halved copies so thermal-printer dots merge (dots read at
   full photo resolution: the likely cause of the user's real-iPhone report "large digits not read", reproduced only on synthetic images).
3. Pass 1: whole frame, scaled so characters are ~34px (down for close-up photos), deskewed, PSM 3.
4. Pass 2: text area ∪ paper scaled to ~38px characters (0.3×–3×), illumination-normalized, ≤3 tiles, PSM 4. Optional PSM 6 pass.
5. Field pass (`rereadKeyRows`): rows grouped (`groupRows`), key rows picked (`pickKeyRows`: date/total/小計/預り/釣り/対象/税,
   large 倍角 print, top rows for the store). Each row: crop snapped to its ink band (`snapToInkRow`), ~40px, PSM 7 read,
   then the value part read with a digits-only whitelist (`NUMERIC_CHARS`); 倍角 rows also tried stretched ×1.9.
6. `combinePasses`: totals cross-checked (お預り−お釣り, 小計, 10%+8% targets). Cash paid agreeing with another figure is used
   as the amount when no total with equal evidence disagrees. Totals <¥10 never auto-filled. Large-print amounts without a
   readable label count only with evidence. Rate also confirmed from 内消費税 = V×10/110 or V×8/108. Store: fuzzy vote.
   `normalizeLine` repairs "¥4.006"/"¥4 006" (separator misread), "*"→¥, edge bars "|".
7. Overlay unchanged from v5 (`#ocrFrame`, contain math, ResizeObserver).
- Tesseract.js 5.1.1 facts (verified in its source): `data.lines`/`words` are flattened from `blocks` by `circularize`; `bbox {x0,y0,x1,y1}` and `baseline` exist on lines/words; `hocr`/`tsv` are generated by default (we now disable them); `rotateAuto` would return rotated coordinates (not used).
